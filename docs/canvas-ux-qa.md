# Firefly Canvas V2 UX QA / Heuristic Evaluation

> 基线：`release/candidate-3` + Canvas 交互一致性修复
>
> 方法：Nielsen 10 项启发式、键盘与焦点走查、Chromium/WebKit 真实浏览器回归、生产构建体积核查
>
> 结论：核心创作路径通过；未发现 P0/P1 阻塞，已知限制列在文末。

## 1. 覆盖范围

- 画布载入、空态、错误重试、只读、编辑权接管与网络恢复。
- 节点创建、左右引用、弹层定位、缩放/平移、框选、分组、撤销/重做。
- 文本编辑与放大模式、焦点陷阱、Escape、焦点归还和 Markdown 保存。
- 项目资产、批量上传、图片裁剪/旋转、视频抽帧、生成任务和 Montage 入口。
- IndexedDB 本地草稿、服务端自动保存、离页写入和冲突恢复。
- 桌面 Chromium、Edge 同内核与 WebKit；移动端只读行为由响应式规则覆盖。

## 3. 本轮修复

1. 节点加号菜单使用按钮的 viewport 矩形定位，并 Portal 到 `document.body`，不再受 React Flow 变换与工作区裁剪影响。
2. 菜单在窗口边缘自动翻转和夹紧；箭头位置独立计算，始终指向触发加号。画布开始移动、缩放、节点拖动或窗口变化时关闭菜单，避免漂移。
3. 文本放大编辑 Portal 到顶层 Dialog，使用真实全视口遮罩；支持焦点陷阱、Escape 和焦点归还，不再嵌在缩放后的节点坐标系。
4. 隐藏的节点加号在键盘聚焦时变为可见，并提供 `focus-visible` 描边。
5. 缩放百分比改为订阅 React Flow viewport，按钮、滚轮和触控板缩放后读数立即更新。
6. IndexedDB 连接在编辑会话内复用，写入以事务完成为成功标准；`pagehide` 和组件卸载前立即写本地草稿。
7. Lexical 与 Montage 改为按需加载。Canvas 基础 JavaScript 从约 595 KB 降至约 297 KB；文本编辑器约 287 KB、Montage 约 11 KB 仅在使用时加载。
8. 图片裁剪/旋转、视频抽帧继续使用 Dedicated Worker、OffscreenCanvas、createImageBitmap 与 Blob URL；结果先在画布即时显示，再异步直传 TOS。

## 4. 验证记录

- `npm run typecheck`：前后端通过。
- `npm run build`：生产构建通过；浏览器 Worker 和按需功能均生成独立 chunk。
- `npm test -- --maxWorkers=1`：45 个测试文件、219 项测试全部通过。
- Playwright Chromium：6/6 Canvas V2 场景通过。
- Playwright WebKit：6/6 Canvas V2 场景通过；允许不同引擎最多 1px 的亚像素舍入差异。
- 浏览器断言覆盖：菜单 Portal、加号锚定、箭头中心、移动后关闭、实时缩放读数、文本全屏编辑、真实引用关系、离页草稿提交和租约恢复。

## 5. 已知限制与后续观测

1. 浏览器不支持 WebCodecs 或 OffscreenCanvas 时，基础画布仍可编辑，但抽帧和 Montage 会要求升级浏览器；不会静默回退到 AWS 转码。
2. 浏览器本地派生图在当前标签页会即时显示；若在其 TOS 上传完成前强制关闭标签页，本地 Blob 不跨会话恢复。普通文本、布局和引用草稿不受影响。
3. 500 节点性能目标由 React Flow 可视区域渲染、memo 和媒体懒加载保障；仍需上线后用真实低配办公机补充 Long Task 与内存遥测基线。
4. Safari/WebKit 的冷启动自动化明显慢于 Chromium，但生产按需拆包后基础画布下载量已减半；需结合真实访问日志继续观察资源命中率。

## 6. 发布验收点

- 点击左右加号后，菜单与按钮水平间距约 10px；边缘自动翻转，箭头中心误差不超过 1px。
- 菜单打开后缩放、平移或拖动节点，不得留下悬空菜单。
- 文本放大编辑必须覆盖完整浏览器可视区，不得存在于 `.react-flow__node` 内。
- 最后一次文本编辑后立即触发 `pagehide`，IndexedDB 中必须存在对应草稿。
- 首次进入无文本节点的画布不得下载 Lexical chunk；未打开 Montage 不得下载 Montage 组件 chunk。
- 所有弹层可使用 Escape 关闭，并将焦点归还到原触发控件。
