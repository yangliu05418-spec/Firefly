# Firefly Studio 上线评估（CTO 视角）

> 评估日期：2026-08-18 · 评估对象：fix/review-round-1 HEAD（3d5774d）
> 结论：**有条件通过 —— 可以受限内部上线**（企业 SSO + 白名单域名 + 小规模），
> 前置 2 项操作项 + 1 项建议演练；5 项技术债在首个发布迭代内偿还。

## 1. 结论摘要

该工程已具备生产级代码质量与部署资产（多阶段镜像、compose 编排、Redis AOF、SQLite 一致性备份、
nginx HTTPS、TOS 生命周期分层、成本并发上限、0 生产依赖漏洞），且此前已有真实部署痕迹
（firefly-production-*.png 截图与 release tgz）。

**判断**：达到「受限内部发布」标准，可上线运行。门槛设定依据：
- 准入完全受控：仅飞书企业 SSO（dokuai.tv 白名单），无公开注册入口
- 成本可防护：每用户并发生成上限 4（429）+ 全局队列并发 4
- 数据可恢复：SQLite 每 6h 一致性备份至 TOS backups/（长期）+ 完整性校验 + SHA256
- 代码有门禁：125 测试全绿、类型检查零错误、生产依赖 0 漏洞（官方 registry 审计）

## 3. 剩余工程里程碑（按优先级）

### 里程碑 A：上线护航（首个迭代，1–2 周）
- CI/CD 门禁：GitHub Actions（test + 前后端类型检查 + 构建 + 镜像推送），消除「无自动化门禁」风险
- 可观测性：队列深度/生成延迟/归档失败率指标 + 告警；错误追踪（Sentry 或自建最小方案）
- 前端类型检查门禁修复：tsconfig project reference composite 问题，把 typecheck 固化进脚本与 CI
- 管理面：BullMQ 队列看板（Arena/Board）；任务级「人工重新归档」入口（当前恢复封顶后无人工路径）

### 里程碑 B：质量加固（第二迭代）
- E2E 冒烟测试：登录 → 上传 → 生成 → 归档 → 预览 → 画布插入 全链路（Playwright）
- 保留策略：软删任务/媒体对象定期清理任务（TOS 生命周期已覆盖 inputs；库内软删行需归档策略）
- App.tsx 拆分（700+ 行单文件 → 按视图分模块），eslint 引入
- 会话管理增强：SESSION_SECRET 轮换脚本、异常登录告警

### 里程碑 C：规模化（用户数显著增长后）
- 生成历史分页/虚拟滚动；SQLite → 归档分库评估；多实例部署（当前单实例 + 队列消费模型）
- 素材审计与共享报表；Canvas 实时协作

## 4. 技术债务登记

| 等级 | 债务 | 现状与影响 |
|---|---|---|
| P1 | 无 CI/CD | 无自动化门禁，回归风险靠人工；分支 8 条未合并，合并策略待定 |
| P1 | 可观测性缺失 | 仅有结构化日志；无指标/告警/错误追踪，故障发现靠巡检 |
| P1 | 前端无类型检查门禁 | tsconfig 引用损坏（composite），typecheck 仅靠临时配置手动跑 |
| P2 | 无 E2E | 关键链路无冒烟测试，发布前靠人工验证 |
| P2 | 管理工具单薄 | 用户停用仅 CLI；无任务恢复/队列管理 UI；恢复耗尽的任务无人工入口 |
| P2 | App.tsx 单文件 | 700+ 行；canvas 已独立 feature，其余视图仍集中 |
| P2 | registry 配置 | 当前 npmmirror 不支持 npm audit（官方 registry 审计为 0 漏洞）；CI 需固定官方源 |
| P3 | 会话/密钥 | SESSION_SECRET 静态；无吊销列表；建议轮换机制 |
| P3 | 软删数据积累 | 软删任务/媒体行无归档清理周期（history:clear 为手动全清） |
